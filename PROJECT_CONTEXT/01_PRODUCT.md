# DELTA

## What is Delta?

Delta is a Knowledge Operating System (Knowledge OS) for Architecture Projects.

Delta is built to transform fragmented project information into structured knowledge that can be understood, connected, searched and reused throughout the lifecycle of a project.

Delta is not a chat application.

Delta is not a document management system.

Delta is not a project management application.

Documents, meetings and conversations are treated as evidence.

Knowledge is the primary product.

---

# Core Philosophy

Architecture projects continuously generate information.

Emails.

Meetings.

Drawings.

Site discussions.

WhatsApp messages.

Client comments.

Specifications.

Traditionally this information is scattered across many systems.

Delta continuously converts this evidence into structured project knowledge.

The flow is:

Evidence

↓

Knowledge Review

↓

Knowledge Objects

↓

Knowledge Evolution

↓

Knowledge Graph

↓

Project Intelligence

Every feature added to Delta must strengthen this knowledge pipeline.

---

# Product Principles

## Evidence First

Everything begins as evidence.

Evidence is never considered knowledge until reviewed.

Examples of evidence:

- Meetings
- Emails
- Drawings
- Site Photos
- PDFs
- Client Messages
- RFIs
- Specifications

Evidence is immutable.

---

## Knowledge is Curated

Knowledge is reviewed before becoming part of the project.

Knowledge Objects include:

- Requirements
- Decisions
- Concepts
- Spaces
- Constraints
- Risks
- Assumptions
- Agreements

Knowledge is versioned.

Knowledge has provenance.

Knowledge always links back to evidence.

---

## Relationships Matter

Knowledge becomes valuable when connected.

Every knowledge object should have meaningful relationships.

Examples:

Requirement

↓

Decision

↓

Drawing

↓

Meeting

↓

Client Query

Delta should continuously strengthen these relationships.

---

## Knowledge Evolution

Projects evolve through decisions.

The Project Evolution timeline represents verified changes in project knowledge.

The timeline is historical.

It is not a project schedule.

It is not a task list.

It is not an activity log.

Only meaningful knowledge milestones appear.

Examples:

Requirement Approved

Decision Approved

Client Query Raised

Drawing Approved

Review Package Merged

Variation Approved

Milestones are added over time.

Future milestones are never shown.

---

## Workspace Philosophy

Delta is one continuous workspace.

Users should rarely navigate between pages.

The primary workspace consists of:

Sidebar

↓

Evolution Strip

↓

Project Journal

↓

Delta Assistant

Every part of the workspace should reinforce project understanding.

# Delta Assistant

Delta is not a chatbot.

Delta is an architectural intelligence assistant.

Delta should:

Summarize

Explain

Connect

Recommend

Search

Reason

Delta should never become the focus.

The project should remain the focus.
